02 AI & agents

I don't just spec agents. I read their traces.

Evals
Test questions with known answers for my domain, graded on correctness, groundedness, scope and refusals — so a change is judged on evidence, not on a demo.
Traces
I read agent runs span by span to catch invented values, routing errors and the same question getting two different answers.
Mandates
What an agent may do for a user: read-only or acting, whether an action can be reverted, and when a human must confirm.
Automation classes
Assist, one-click, two-turn and scheduled — each capability gets the lightest class its risk allows.
Tools & MCP
Domain data behind MCP tools the agent calls, so answers come from the source, not from the model's memory.
Context
Personas, playbooks under a token budget, what an agent is not for and where it hands over.
Human-in-the-loop
Human review on critical paths until there are enough traces to trust an LLM judge.
Skills for PMs
I wrote the Claude skills rolled out to every PM in our unit, to define their domain's agent and to decide when a change needs a spec.
