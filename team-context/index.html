Proof of concept · MCP · Read-only

Stop being your team's lookup service.

An MCP server that lets Toqan, the company assistant at OLX, answer questions about my team from my own wiki. Six read-only tools, and a hard allow-list deciding what it can ever see.

Built with
Python · FastMCP · streamable HTTP
Surface
6 tools, all read-only
Boundary
Allow-list in code, not config
Status
Proof of concept

Note. The wiki behind this is internal. Nothing from it appears here — no pages, no names, no numbers. What follows is the interface and the boundary only.

Model Context Protocol✳ Read-only✳ Allow-list, not deny-list✳ No writes, ever✳ The platform's edge is not the edge✳
01Why

Toqan can reach the tools the platform team connected. It cannot reach my team's context — what we are building, which stage each initiative is at, what a metric means here. So every stakeholder question came to me.

The edge of the platform is not the edge of what you can build. MCP is the seam: anything I can reach, my agent can reach. So I put a server in front of the curated half of my wiki and let people ask it directly.

02The surface

Six tools. Every one reads; none writes. Each returns JSON, so the assistant gets structure rather than a wall of Markdown to guess at.

  • list_pages()

    Every page the boundary allows. The only way to discover a valid path.

  • read_page(path)

    One page, by a path that list_pages() returned.

  • search_wiki(query)

    Full-text search, scoped to the same allowed set.

  • team_summary()

    Identity, mission, initiatives, metrics and markets in one structured answer.

  • get_okrs()

    Objectives, key results, bets and strategic themes.

  • what_we_are_working_on()

    Initiatives with in-flight work ranked first — the question people actually ask.

03The boundary

This is the part that mattered. The wiki holds meeting notes, personal pages and raw transcripts next to the curated pages. Exposing it to the whole company meant deciding, in code, exactly what a caller may ever see.

Reachable
  • org/
  • projects/
  • metrics/
  • product/
  • strategy/
  • index.md
  • markets.md
  • README.md
  • SCHEMA.md

Curated pages only — the half of the wiki that is meant to be the answer to a question.

Unreachable
  • meetings/
  • work/
  • raw/
  • people/
  • commitments
  • agent config
  • .git/
  • .obsidian/

Transcripts, personal pages, drafts and my own instructions to the agent. None of it is anyone else's business.

04What stops a clever caller

An allow-list only holds if the path that reaches it cannot be bent. Six guards, each for a specific way in.

  • Enumerate, don't traverse

    The server walks the allowed folders and nothing else. A blocked path is not refused — it is never visited, so it never appears in any result.

  • Deny-list as a second layer

    Redundant by design. If the allow-list were ever loosened by mistake, the sensitive names are still rejected outright.

  • No traversal, no absolutes

    .., leading slashes, Windows drive letters and backslashes are all rejected before the filesystem is touched at all.

  • Case-folded matching

    macOS filesystems are case-insensitive. Without folding, a different capitalisation is a bypass. Every comparison is folded.

  • Symlinks refused, roots checked

    Symlinks are skipped, and every resolved path is re-checked against the wiki root — so a link cannot walk out of the allowed tree.

  • Filtering at paragraph level

    The summary tools read allowed pages, but an allowed page can quote a blocked one. Any paragraph referencing an excluded source is dropped before the answer is built.

05What it showed
  • A PM can extend the platform. The assistant the company gives you is not the limit of what it can answer. MCP is the seam, and it is a 200-line Python file, not a project.
  • The hard part is not the protocol. Standing the server up took an afternoon. Deciding what a stranger's agent may read from your team's notes took longer, and is the part worth reviewing.
  • Read-only is a feature. With no write path in the code, the worst case is a wrong answer rather than a changed system.
  • It is a proof of concept, not a product. It runs on my laptop behind a tunnel. It exists to show the shape of the thing — the platform team owns what happens next.
